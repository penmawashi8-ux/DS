# オリジナル問題 午後 問1

> 本サイトで作成したオリジナル問題（IPAの過去問ではない）。新形式の午後（問1〜問4から2問選択・150分）の1問を想定した分量。

**問1 ソフトウェアサプライチェーンのセキュリティに関する次の記述を読んで，設問に答えよ。**

K社は，従業員1,500名の業務用ネットワークカメラ（以下，カメラという）の製造販売会社である。カメラは，ビル管理会社や小売業者に販売されている。カメラの主な製品を表1に示す。

**表1 カメラの主な製品**

| 製品名 | 発売年 | 概要 |
|---|---|---|
| KC-100 | 2019年 | 屋内用。ファームウェアはバージョン3系 |
| KC-200 | 2022年 | 屋内・屋外兼用。ファームウェアはバージョン4系 |
| KC-300 | 2025年 | 屋外用。AIによる人物検知機能付き。ファームウェアはバージョン5系 |

カメラのファームウェアは，LinuxベースのOSの上で，K社が開発したプログラムと多数のOSSで構成されている。ファームウェアの開発は開発部が，出荷後の製品の品質対応は品質保証部が担当している。

## 〔脆弱性への対応の遅れ〕

昨年，画像処理用のOSSであるlibimgに，深刻な脆弱性（以下，脆弱性Pという）が公表された。顧客から“自社のカメラは脆弱性Pの影響を受けるか”という問合せが多数寄せられたが，K社では，各製品のファームウェアにどのOSSのどのバージョンが含まれているかを一覧にした資料がなかった。開発部が各製品のソースコードを調べて回答するまでに3週間掛かった。

さらに，KC-100については，当初“libimgは使用していない”と回答したが，後に使用していることが分かり，回答を訂正した。KC-100の開発当時，libimgのソースコードを入手して一部を改変し，K社のソースコードの中にコピーして組み込んでいたことが原因であった。

この件を受けて，K社は品質保証部の中に製品のセキュリティ対応を行うPSIRTを設置した。PSIRTのリーダーには品質保証部のM課長が，メンバーにはNさんが任命された。また，外部の情報処理安全確保支援士（登録セキスペ）であるS氏の支援を受けることになった。

## 〔SBOMの導入〕

PSIRTは，各製品のファームウェアの構成要素を把握するために，SBOM（Software Bill of Materials）を導入することにした。SBOMの形式には，Linux Foundationが策定し，ISO/IEC 5962として国際標準化された［　a　］を採用する。SBOMに記載する主な項目を表2に示す。

**表2 SBOMに記載する主な項目**

| 項目 | 内容 |
|---|---|
| 構成要素名 | OSS及びK社が開発したプログラムの名称 |
| バージョン | 構成要素のバージョン |
| 供給者 | 構成要素の開発元 |
| 識別子 | 構成要素を一意に識別するためのPURL（Package URL） |
| ライセンス | 構成要素のライセンス |
| 依存関係 | 構成要素間の依存関係 |
| ハッシュ値 | SBOMの対象であるファームウェアイメージのSHA-256によるハッシュ値 |

Nさんは，SBOMの作成手順案を図1のとおりまとめた。

```
1. ビルドサーバでファームウェアをビルドする際に，パッケージ管理ツールの依存関係定義ファイ
   ル（以下，マニフェストという）を解析し，K社のプログラムが直接依存しているOSSの名称と
   バージョンの一覧を出力する。
2. 1.の一覧を表2の項目に沿って［ a ］形式に変換し，SBOMとする。
3. SBOMは，開発部のファイルサーバに製品名ごとのフォルダを作成して保存する。
```

**図1 SBOMの作成手順案**

次は，図1についてのS氏とNさんの会話である。

S氏　：この手順では，昨年の脆弱性Pのときと同じように，<u>①KC-100に含まれるlibimgがSBOMに記載されない</u>ことになります。ビルド成果物を解析して，OSSのコードが含まれていないかを検出するツールを併用してください。

Nさん：分かりました。

S氏　：それから，手順1で一覧にするのは直接依存しているOSSだけですね。それでは，<u>②SBOMに記載されないOSSがほかにもあります</u>。依存関係をたどれるツールを使ってください。

Nさん：はい。手順3についてはどうでしょうか。

S氏　：ファームウェアは同じ製品でも頻繁に更新されるので，製品名ごとのフォルダに保存するだけでは，どのSBOMがどのファームウェアのものか分からなくなります。表2のとおり<u>③ファームウェアイメージのハッシュ値をSBOMに記載しておく</u>とよいでしょう。

Nさんは，S氏の助言を基に図1を修正し，リリースするファームウェアごとにSBOMを作成することにした。

## 〔脆弱性情報との照合〕

PSIRTは，毎日，公開されている脆弱性情報を取得し，SBOMの構成要素と照合することにした。脆弱性情報データベースの一つであるNVDでは，影響を受ける製品やソフトウェアを，［　b　］と呼ばれる構造化された名称で表している。一方，K社のSBOMではPURLを識別子として使っているので，照合のためには，両者の対応付けが必要である。

照合を開始したところ，KC-200の最新のファームウェアについて，表3に示す四つの脆弱性が見つかった。

**表3 KC-200のファームウェアで見つかった脆弱性**

| 番号 | 構成要素 | CVSS v3.1 基本値 | 脆弱性の概要 | KEV<sup>1)</sup>への掲載 |
|---|---|---|---|---|
| V1 | libtls 3.0.2 | 9.8 | TLSサーバとして動作しているときに，細工されたハンドシェイクメッセージを受信すると，任意のコードが実行される。 | なし |
| V2 | libjson 1.4.0 | 7.5 | 細工されたJSONデータを解析すると，無限ループに陥り，サービス停止となる。 | なし |
| V3 | libimg 2.1.0 | 6.5 | 細工された画像ファイルを読み込むと，メモリ上の情報が漏えいする。 | あり |
| V4 | busybox 1.31.0 | 8.8 | 同梱のtelnetdに，認証を回避してログインできる脆弱性がある。 | なし |

注<sup>1)</sup> 米国CISAが公開している，実際に悪用されたことが確認された脆弱性のカタログ（Known Exploited Vulnerabilities Catalog）

Nさんは，開発部に確認し，KC-200での各構成要素の使われ方を表4のとおりまとめた。

**表4 KC-200での各構成要素の使われ方**

| 構成要素 | 使われ方 |
|---|---|
| libtls | 録画データをクラウドストレージに送信する際の，TLSクライアントとしてだけ使用している。Web管理画面のHTTPS通信は，Webサーバプログラムに組み込まれた別のTLSライブラリで処理している。 |
| libjson | Web管理画面で，ログイン後に設定内容をJSON形式で受け付ける処理に使用している。 |
| libimg | カメラ映像の縮小処理と，Web管理画面から管理者がアップロードするロゴ画像ファイルの読込みに使用している。 |
| busybox | OSの基本コマンド群として使用している。telnetdも含まれているが，出荷時設定では起動しない。ただし，Web管理画面で“保守モード”を有効にすると，保守作業用にtelnetdが起動する。 |

Nさんは，CVSS基本値の高い順にV1，V4，V2，V3の順で対応しようと考え，S氏に相談した。次は，その時の会話である。

S氏　：まず，各脆弱性が製品に影響するかどうかを判断しましょう。影響しないものは，その判断と根拠を顧客に伝えると，問合せが減ります。製品が個々の脆弱性の影響を受けるかどうかを機械可読な形式で伝える文書を［　c　］といいます。SBOMと組み合わせて使われています。

Nさん：表4から考えると，<u>④V1はKC-200には影響しない</u>と判断できます。V4もtelnetdが出荷時設定では起動しないので，影響しないと判断してよいでしょうか。

S氏　：<u>⑤V4は，影響しないとは判断できません</u>。対応が必要です。

Nさん：分かりました。対応の順番はCVSS基本値の高い順でよいでしょうか。

S氏　：CVSS基本値だけで決めるのはよくありません。<u>⑥V3は，CVSS基本値は低いですが，最優先で対応すべき</u>です。

PSIRTは，S氏の助言を基に，V3，V4，V2の順で修正版のファームウェアを開発するよう開発部に依頼し，V1については影響しない旨を［　c　］で公表することにした。

## 〔顧客へのSBOMの提供〕

ある日，大口顧客であるビル管理会社のT社から，“導入済みのカメラについて，SBOMを提供してほしい”という要望があった。T社では，自社で利用する機器の構成要素を把握し，脆弱性が公表されたときに影響の有無を自ら速やかに判断したいとのことであった。

Nさんは，各製品のSBOMをK社のWebサイトで誰でもダウンロードできるように公開することを提案した。しかし，M課長は，<u>⑦SBOMを誰でもダウンロードできるようにすることにはリスクがある</u>と指摘した。検討の結果，SBOMは，契約している顧客だけがログインして利用できる顧客ポータルで提供することにした。また，提供するSBOMには［　d　］を付与し，T社などの顧客が，SBOMがK社によって作成され，改ざんされていないことを確認できるようにした。
