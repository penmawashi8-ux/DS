## 問1 セキュリティインシデント（J社 / 保守用中継サーバへの不正アクセス）

| 設問 | 解答 |
|---|---|
| 設問1(1) | a：接続先が保守用中継サーバではない |
| 設問1(2) | 操作ログの改ざんや削除を防止するため |
| 設問1(3) | b：保守PC-A　c：インターネット |
| 設問2(1) | 6 |
| 設問2(2) | 6月14日の7時0分から6月14日の9時30分まで |
| 設問3(1) | 保守員以外が不正に秘密鍵を利用できないようにするため（又は，秘密鍵が盗まれても悪用できないようにするため） |
| 設問3(2) | d：パスワード認証 |
| 設問3(3) | e：秘密鍵 |
| 設問3(4) | f：送信元IPアドレスを固定にする |

### 解説

#### 設問1(1)　［知識］
> 本文：図2 5「SSH接続する際に**警告メッセージ**が表示され，接続が切断された場合，保守用中継サーバの**フィンガプリントが変わった**か，［ a ］という状況が想定される」

**知識**：SSHのクライアントは，初回に確認したサーバのフィンガプリント（ホスト鍵）を覚えておき，次から照合する。違う鍵が出てきたら警告を出す。正規のサーバが鍵を変えたか，**別のサーバ（なりすまし・中間者）につながっている**かのどちらか（採点講評でも「稼働していない」という誤りが多かった）。

**答え**：a：接続先が保守用中継サーバではない

#### 設問1(2)　［読解］
> 本文：図2「保守用中継サーバでのコマンド実行…が，**保守用中継サーバ上に操作ログ**として記録される」「SSH認証ログ及び操作ログへのアクセスには**特権利用者の権限**が必要」

**考え方**：操作ログは保守員が使う中継サーバ上にある。保守員が特権を持っていると，自分の操作の記録を消したり書き換えたりできてしまう。一般利用者にしておけば手が出せない。

**答え**：操作ログの改ざんや削除を防止するため

#### 設問1(3)　［読解］
> 本文：表1 項番3「［ b ］→保守用中継サーバ　SSH　**許可**」，項番4「［ c ］→保守用中継サーバ　SSH　**拒否**（保守PC-B又は保守PC-Cからの保守作業の際は…作業時間帯だけ…“許可”に変更）」，図1 保守PC-AはPC-LAN，保守PC-B・Cはスマートフォン経由でインターネット

**考え方**：社内の保守PC-Aはいつでも許可。インターネットから来る保守PC-B・Cは，申請された時間帯だけ許可に変える。

**答え**：b：保守PC-A　c：インターネット

#### 設問2(1)　［読解］
> 本文：表1 項番6「**DMZ→インターネット**　全て　拒否　ログの記録 する」，注記2「項番7〜14には，保守用中継サーバ，DMZ，SSHに関するルールはない」

**考え方**：プログラムHは保守用中継サーバ（DMZ）からインターネットへ通信しようとした。これに当たるのは項番6で，拒否されつつログに残った。

**答え**：6

#### 設問2(2)　［読解］
> 本文：図3「保守PC-Cを使って6月14日**7時から9時30分**に行うという事前申請…J社のシステム管理者はFWの設定を変更した」，表1 注1「事前申請に記載された**作業時間帯だけ**…“許可”に変更」

**考え方**：インターネットからSSH接続できたのは，項番4を許可にしていた7時0分から9時30分まで。実際に認証に成功したのは7時40分だが，問われているのは接続可能だった期間。

**答え**：6月14日の7時0分から6月14日の9時30分まで

#### 設問3(1)　［知識］
> 本文：図5「公開鍵認証に使う鍵ペアは，各保守員が保守PCごとに作成し，管理する」「③鍵ペアの**秘密鍵**には，十分な強度の**パスフレーズ**を設定する」

**知識**：パスフレーズは秘密鍵のファイル自体を暗号化する。保守PCが盗まれたり，秘密鍵のファイルがコピーされたりしても，パスフレーズを知らなければ使えない。パスフレーズはサーバに送られない（採点講評でもその誤りが指摘されている）。

**答え**：保守員以外が不正に秘密鍵を利用できないようにするため

#### 設問3(2)　［読解］
> 本文：「SSH接続の認証方式を，**パスワード認証から公開鍵認証に変更**する」，図4「op1に設定されているパスワードが，**推測の容易な**文字列」

**考え方**：公開鍵認証を有効にしても，パスワード認証が残っていれば，今回と同じようにパスワード推測で入られる。無効にする。

**答え**：d：パスワード認証

#### 設問3(3)　［知識］
> 本文：S氏「顧客管理サーバへのSSH接続に必要な［ e ］を利用されないように，**保守用中継サーバに保存しない**運用」「**SSH Agent Forwarding**…保守作業のSSH接続に必要な［ e ］の全てを**保守PCにだけ保存**」

**知識**：SSH Agent Forwardingは，中継サーバから先のサーバへの公開鍵認証の署名を，手元のPCのSSHエージェントにやらせる機能。中継サーバに**秘密鍵**を置かずに多段接続できる。

**答え**：e：秘密鍵

#### 設問3(4)　［読解］
> 本文：図2「保守PC-B及び保守PC-Cは…テザリングし…**固定のグローバルIPアドレスは付与されない**」
> 本文：「保守PC-B及び保守PC-Cを，VPN装置を介して又は直接，**M社内のネットワーク**に接続させた後に…アクセスさせる」「表1の**項番4のルールを変更**することによって制限できる」

**考え方**：接続元がばらばらのIPアドレスだと，FWで絞れない。M社のネットワークから出るときの送信元IPアドレスが固定なら，項番4の送信元を「インターネット」からそのIPアドレスに絞れる。

**答え**：f：送信元IPアドレスを固定にする

## 問2 システム開発での情報漏えい対策（R社 / IRM）

| 設問 | 解答 |
|---|---|
| 設問1 | a：Pパスワードの変更　b：PCにコピー |
| 設問2(1) | アカウント：ア，イ　操作：プロジェクト離任者の利用者アカウントをグループから削除する。 |
| 設問2(2) | (ii) |
| 設問2(3) | c：60　d：196 |
| 設問2(4) | e：辞書 |
| 設問2(5) | f：多要素認証 |
| 設問3 | 利用者がファイルを開いたとき，画面をキャプチャし，攻撃者に送信する動作 |

### 解説

#### 設問1　［読解］
> 本文：「設計秘密には，プロジェクト単位のパスワード（Pパスワード）を使用する」「プロジェクトを離任する者が出た場合には…離任者がアクセスできないようにする」
> 本文：「設計秘密は…R社のネットワーク内の**ファイルサーバだけに保管**する」（規則）

**考え方**：
- a：離任者はPパスワードを知っているので，読めなくするには全ファイルのPパスワードを変える必要がある。
- b：規則に反して自分のPCにコピーしたファイルは，ファイルサーバの権限を外しても手元に残り，Pパスワードも分かっているので開けてしまう。

**答え**：a：Pパスワードの変更　b：PCにコピー

#### 設問2(1)(2)　［読解］
> 本文：図1 2「グループ管理者アカウント…利用者アカウントをグループに所属させたり，**グループから削除**したりできる」「IRM管理者アカウント…全てのグループに対して，**グループ管理者アカウントと同様の権限**」，4「ファイルの利用権限が…選択した**グループ**に付与」
> 本文：図1 5(ii)「IRMサーバでは…**利用者アカウントがファイルに対する権限をもっている場合に**，IRMサーバ秘密鍵でコンテンツ鍵が復号される」

**考え方**：権限はグループに付いているので，離任者をそのプロジェクトのグループから外すだけでよい。それができるのはグループ管理者とIRM管理者。外された利用者がファイルを開こうとすると，(ii)で権限がないためコンテンツ鍵が復号されず，PCにコピーしたファイルでも読めない（問題4の解決）。

**答え**：(1) ア，イ／プロジェクト離任者の利用者アカウントをグループから削除する。　(2) (ii)

#### 設問2(3)　［読解］（計算）
> 本文：図2「Pパスワードが**文字種64種類で長さ10字**とすると，Pパスワードの推測には最大で2の［ c ］乗」「RSA-2048を破るには，**2の112乗**」，正誤表で追加「しかし，**暗号化されたコンテンツ鍵は入手できない**と考えてよい」

**考え方**：
- c：64＝2の6乗。10字なので (2⁶)¹⁰＝2の60乗。
- d：Wソフトは弱いほう（パスワード推測の2の60乗）で破れる。IRM-Lは，暗号化されたコンテンツ鍵が入手できないのでRSAを破る道はなく，コンテンツ鍵の総当たり（2の256乗）しかない。256−60＝196。

**答え**：c：60　d：196

#### 設問2(4)(5)　［知識］
> 本文：「一定時間当たりの**ログイン試行回数を制限**する機能や，一定回数のログイン失敗で**アカウントをロック**する機能」「**推測が容易なパスワード**を利用者が設定してしまうと，長さが10字であったとしても［ e ］攻撃に対して脆弱」

**知識**：試行回数が制限されていても，よく使われる単語やパターンから先に試す**辞書攻撃**なら，推測しやすいパスワードは少ない回数で当たる（採点講評：ブルートフォースは回数制限で防げるので不適）。パスワードだけに頼らない**多要素認証**にすれば，パスワードが当たっても入れない。

**答え**：e：辞書　f：多要素認証

#### 設問3　［読解］
> 本文：図1 5(v)「IRMクライアントでは，コンテンツ鍵で対象ファイルが**復号**される」，(vi)「復号されたファイルに対しては，参照又は編集後に再びファイル暗号化」

**考え方**：IRMでも，正規の利用者が開いている間はファイルの中身が画面に表示される。そのPCに感染したマルウェアが画面を撮影して外へ送れば，暗号を破らなくても内容が漏れる。

**答え**：利用者がファイルを開いたとき，画面をキャプチャし，攻撃者に送信する動作

## 問3 PCのマルウェア対策（Q社 / マルウェアXの感染対応）

| 設問 | 解答 |
|---|---|
| 設問1(1) | LANから切り離す。 |
| 設問1(2) | ディスクイメージ |
| 設問1(3) | a：最新のマルウェア定義ファイルを保存したDVD-Rの使用　b：マルウェア定義ファイルの更新　c：マルウェア対策ソフトの画面の操作 |
| 設問1(4) | Q社内の全てのPC及びサーバからのアクセス |
| 設問2(1) | ①項番3　送信元：総務部LAN，営業部LAN　②項番4　送信元：技術部LAN |
| 設問2(2) | d：V社配布サイトのURL　e：全て |
| 設問3(1) | 登録した実行ファイルがバージョンアップされた場合 |
| 設問3(2) | 登録した実行ファイルのマクロとして実行されるマルウェア |

### 解説

#### 設問1(1)(2)　［知識］
> 本文：下線①「マルウェア感染**拡大防止**のためのPC-Gの初動対応」，下線②「ディジタルフォレンジックスによる調査を行うことにして**必要な情報**を取得」

**知識**：感染が疑われる端末は，まず**ネットワークから切り離し**て他への感染や通信を止める（電源は切らない）。フォレンジック調査では，証拠を変えないよう，ディスク全体をそのままコピーした**ディスクイメージ**を取得して調べる。

**答え**：(1) LANから切り離す。　(2) ディスクイメージ

#### 設問1(3)　［読解］
> 本文：「別のPCを用いてマルウェア定義ファイルをV社配布サイトから手動でダウンロードし，そのファイルを保存した**DVD-R**を用いて更新することもできる」「マルウェア対策ソフトの**画面の操作**によってマルウェア定義ファイルを手動で更新することもできる」
> 本文：図3「V社は，マルウェアXに対応したマルウェア定義ファイルを12月9日10時にリリース」

**考え方**：
- a，b：PC-GはLANから切り離しているのでネット経由で更新できない。別PCで最新の定義ファイルをDVD-Rに入れて更新してからフルスキャンする。
- c：全社のPCはネットにつながっているので，画面の操作で手動更新すればよい（9時の自動更新はリリース前なので最新ではない）。

**答え**：a：最新のマルウェア定義ファイルを保存したDVD-Rの使用　b：マルウェア定義ファイルの更新　c：マルウェア対策ソフトの画面の操作

#### 設問1(4)　［読解］
> 本文：図3(4)「アクセス元IPアドレスが**PC-Gである**アクセスを…調査した」
> 本文：図3(2)「hostsファイルに登録されている機器へのログインを試行する。ログインが成功すると，その機器から…C&Cサーバにアップロードする」，「hostsファイルには，プロキシサーバ，Fサーバ1及びFサーバ2」

**考え方**：PC-Gだけ調べても，ほかの感染PCや，ログインされたサーバからC&Cへ通信していたら見逃す。社内の全PC・サーバからのCリストへのアクセスを調べる。

**答え**：Q社内の全てのPC及びサーバからのアクセス

#### 設問2(1)　［読解］
> 本文：「Fサーバ1の利用者を**総務部員及び営業部員**に，Fサーバ2の利用者を**技術部員**に」，表2 項番3「総務部LAN，営業部LAN，技術部LAN→Fサーバ1」，項番4「…→Fサーバ2」

**答え**：①項番3：総務部LAN，営業部LAN　②項番4：技術部LAN

#### 設問2(2)　［読解］
> 本文：「Fサーバ1及びFサーバ2がインターネットと通信するのは，**マルウェア定義ファイルの更新時だけ**」「V社のマルウェア定義ファイル配布サイト（V社配布サイト）」
> 本文：表1「管理者拒否リストに“**全て**”と記載すると，管理者許可リストで許可したURL以外のURLへのアクセスが拒否」

**答え**：d：V社配布サイトのURL　e：全て

#### 設問3　［読解］＋［知識］
> 本文：Yソフト「あらかじめ登録した実行ファイルだけの実行を，**ファイルのハッシュ値を比較**することによって許可」

**考え方**：
- (1) 正規のソフトでもバージョンアップで中身が変わるとハッシュ値が変わり，実行できなくなる。登録し直しが要る。
- (2) 実行ファイル自体は正規のまま，その中で動く**マクロ**（文書ファイル内のマクロなど）として動くマルウェアは，許可されたプログラムの上で動くので止められない（採点講評でも正答率が低かった）。

**答え**：(1) 登録した実行ファイルがバージョンアップされた場合　(2) 登録した実行ファイルのマクロとして実行されるマルウェア
